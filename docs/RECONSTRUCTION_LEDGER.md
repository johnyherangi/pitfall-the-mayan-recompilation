## Approximated

| item | what differs |
|------|--------------|
| Engine exits inside the logic tick | `engineExit` unwinds the tick at once; the port runs the tick out and skips only its end (`0x4363bd`) |
| "PAUSED", the frame rate / position text | the Win32 front end draws them as the original, with `TextOutA` in the font WinMain makes (20 px, the Roman family) in the palette's nearest red; the SDL front end in the 8×8 font at the same place; the frame rate counts the frames composed against the wall clock as the original's `timeGetTime` |
| Audio | software mixer instead of Miles (the samples at Option_WavVolume % of 0x7f, the logic's two channels and their priorities, `FUN_004262d9` / `FUN_004261e2`); the CD plays as the original's (the track chosen by level and option, its replay at the end, the stop on a pause, the two-second fade at a level load, the stop-watch's quarter volume): in the Win32 build from the disc itself through MCI when it is in (known by the lengths of tracks 7 and 8, the CD line's aux volume), else, and in the SDL build, from files ripped from it (`TrackNN.wav` / `.ogg`) mixed in at the CD volume; without either the game goes on silent where the original refused to start ("Pitfall must be played using the CD-ROM.") |

| Full-screen modes | DISPDIB's 320×200 and 320×224 modes are both a stretched borderless window keeping the view's shape (Alt+Enter too, an addition); "Sync Full Screen to Monitor" is kept but does nothing; the game always starts in a window, as the original |
| The window's pictures | the About box's (0x7a), the status bar's icons (0x7e), the sliders' slope (0xd4), the pages' icons (207 .. 210) and the cheats' photographs (0x80 / 0x81) come from `PITFALL.EXE` in the data directory; the menu and the dialogs themselves are rebuilt in `pitfall.rc`; the property sheet follows Windows 95 (the priority slider on, the sound on, the full-screen items there) |
| Help | WinHelp of `PITFALL0.HLP` as the original (modern Windows no longer has WinHelp; Wine's shows it) |

## Not ported yet — the rest of the Genesis-derived game logic

The machine-translated 68000 half of the binary (`0x401000–0x437fff`) is ported routine by routine: Harry's
states, the object system and 140 of its behaviour types, the camera and spawner, the triggers and level
scripts, the map screen, the 2600 level, the continue screen, the title, the cutscenes, level 24, the engine's
transitions, CD audio, the typed cheat codes, the parallax's water effects and the original's window (menu, status
bar, dialogs, property sheet) and the disc through MCI.  What is left: a build with MSVC itself (the Windows build
is checked with clang / llvm-mingw, and run under Wine).

The Genesis half's own palette fades (`DAT_0046655e` .. `DAT_00466568`: the death colours, the continue screen's
match, a boss's) are written but never read on the PC (`FUN_004263e3`, the Genesis routine that ran them, is a
`ret`), so they have no effect, nor do the 1-up's stray writes into their tables (`0x41ff34` / `0x41ff56` write
the word 1 at `a0 + 0x5a` / `+ 0x6a`, a0 left in the sparkle table by the same tick's sparkle).  `FUN_00434815`,
the Genesis seeding of the random generator, is unreachable too: its state starts at zero and runs on across
games (the demos advance it too).

## Known gaps in the asset layer

* `.trg` ids other than those listed above; `kTriggerClass` semantics.
* `.als` object *type* handlers for the types listed as not ported.
